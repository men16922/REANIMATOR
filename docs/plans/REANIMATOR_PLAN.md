# REANIMATOR — Abuse 역공학 복원 계획 v3

2026-11-14 · Kiro 인계용 계획 · 게임 구현·원본 분석 미착수

## 1. 만들 것과 범위

**실제 배포된 Abuse DOS 셰어웨어 실행 파일의 핵심 동작을 역공학으로 복원하고, 새로운 3분짜리 2D 공포 액션으로 재해석한다.**

- 대상 게임은 사용자 선택으로 Abuse다. 정확한 배포 버전·실행 파일·해시는 G0에서 확정한다.
- 주 사용자: 설치 없이 짧은 PC 액션을 체험하려는 플레이어. 수요·재미·수상 확률은 아직 검증되지 않았다.
- 제품 작업명: REANIMATOR. 원작의 공식 후속작·리마스터처럼 표시하지 않는다.
- 신규 기여: 실제 바이너리 분석 근거, 검증된 동작 재구현, 새로운 맵·화면·소리·조명 규칙.
- 전체 게임 복원, 범용 자동 리메이크 도구, 3D, 멀티플레이, 결제는 이번 범위에서 제외한다.
- 현재 승인: 계획 작성과 도구 버전 문제 해결. 게임 구현은 사용자가 Kiro에 해당 단계 실행을 지시한 뒤 시작한다.
- 기존 BLACKOUT·REA 작업 트리를 보존한다. 공개·푸시·배포·영상 게시·제출은 사용자 허가 범위에서 실행한다.

## 2. 먼저 성립해야 하는 것

| 항목 | 현재 근거 | 아직 필요한 확인 |
|---|---|---|
| 원본 확보 | DOS 셰어웨어 배포 페이지 존재 | 패키지·버전·실행 파일·해시 |
| 권리 조건 | 원개발사 공개 고지 존재 | 실제 패키지와 파일별 고지 대조 |
| REA 분석 | 로컬 6.9.0 문서에 Ghidra DOS 경로 | Abuse 실제 게임 코드 영역의 로딩·분석 |
| 원본 재현 | 아직 없음 | 에뮬레이터·입력·초기 상태·관찰 시점 |
| 신규 구현 | 아직 없음 | 원본 expected에 접근하지 않는 독립 엔진 |

REA DOS 경로는 16비트 MZ/COM real-mode 범위를 문서화한다. MZ 헤더가 있다고 전체 게임이 16비트라고 가정하지 않는다. DOS extender, 압축, overlay, 내부 실행 모듈 여부를 확인한다. 시작 stub만 읽었다면 게임 분석 성공이 아니다.

**G1에서 원본 게임 코드 한 경로와 실행 행동을 연결하기 전에는 UI 대량 제작을 시작하지 않는다.** 원본 소스를 다시 빌드하거나 현대 SDL 포트를 분석해 원본 바이너리 분석을 대신했다고 주장하지 않는다.

## 3. 플레이 계약

작업 가설: 폐쇄 시설에서 전력 코어를 회수하고 탈출하는 고정 구역 1개. 3분은 목표이며 측정 결과가 아니다.

| 시간 목표 | 플레이 | 확인할 경험 |
|---|---|---|
| 0–20초 | 안전한 공간에서 이동·점프·조준·사격 | 설명보다 조작을 먼저 이해 |
| 20–70초 | 적 1종과 교전, 장애물 통과 | 복원한 움직임·충돌·사격 |
| 70–140초 | 어두운 통로, 조명 선택, 코어 회수 | 새 규칙의 선택과 대가 |
| 140–180초 | 탈출 또는 패배, 즉시 재시작 | 시작부터 끝까지 완결 |

기본 콘텐츠는 무기 1개·적 1종·맵 1개·체력·피격·사망·탈출·재시작이다. 기본 조작안은 A/D 이동, Space 점프, 마우스 조준, 좌클릭 사격, E 조명, Esc 일시정지다. 원본 입력과 신규 UI 입력을 구분한다.

새 규칙안: 조명을 켜면 배터리가 줄고 위험을 읽기 쉬워진다. 끄면 회복되며, 소진 시 꺼진다. 용량·소모·회복·재점등 조건은 G3에서 명세로 고정할 설계값이다. 조명이 원본 이동·충돌·탄약·적 AI를 바꾸지 않게 시작한다. 원작에서 복원한 규칙이라고 설명하지 않는다.

PC 키보드+마우스가 플레이 지원 대상이다. 좁은 화면은 소개·영상·PC 안내를 보장하며 터치 플레이는 약속하지 않는다. 음량 조절·섬광 감소·포커스·키 안내를 제공한다.

| Restoration Lab | 고정 입력·원본 캡처·재구현 비교 | 명시한 동작·필드·구간의 복원 |

첫 화면 주 버튼은 Play다. 원본 영상은 `Recorded DOS reference`, 새 엔진 재생은 `Reimplementation replay`로 표시한다. 새 맵 전체를 원본과 동등하다고 하지 않는다. 에뮬레이터에 원본을 띄우는 것만으로 재구현 완료 처리하지 않는다.

## 5. 기술 구조

- TypeScript + Vite + Canvas 2D 정적 앱. React는 메뉴·근거 패널에만 필요한 경우 사용한다.
- 순수 규칙 엔진을 DOM·렌더링·오디오·실시간 시계와 분리한다.
- 원본 simulation tick을 조사해 복원 테스트에 적용한다. 15/60 Hz를 확인 없이 확정하지 않는다. 렌더링 보간은 별도다.
- 원본 실행은 고정 에뮬레이터 버전·설정·초기 상태에서 수행한다.
- 정적 분석은 REA+지원 provider. 같은 원본의 Ghidra 직접 분석은 제한된 대안이며 REA 사용 여부를 구분한다.
- Python 표준 라이브러리로 근거 도구를 시작하고 실제 최소 버전을 선언한다.
- 패키지 버전은 구현 시작 시 확인해 lockfile에 고정한다. 개발 서버와 원본 실행은 공개 서비스가 아니다.

예정 구조 — 아래 경로는 구현할 위치이며 현재 존재한다고 가정하지 않는다.

```text

reference/fixtures/      # 공개 검토를 마친 입력·관찰 결과
src/engine/             # 순수 재구현 규칙
src/game/               # 새 맵·진행·조명
src/render/             # Canvas·렌더링 보간
src/ui/                 # 시작·결과·근거 화면
tools/reference/        # 캡처·정규화·비교
docs/evidence/          # 실제 분석·실행·Kiro 근거
docs/reconstruction/    # 주소·동작·근거·구현 매핑
```

## 7. G0 상세 순서

1. [실행 가이드](../../REANIMATOR_KIRO_EXECUTION_SPEC.md)의 첫 프롬프트로 `abuse-reference` spec을 만든다.
2. `docs/evidence/environment.md`에 Kiro·Node·REA·provider·에뮬레이터 상태를 기록한다.
3. [출처 등록부](../reference/ABUSE_SOURCE_REGISTER.md)에서 셰어웨어 패키지를 선택하고 `reference/private/`에 보존한다.
4. 압축 목록을 먼저 확인하고 작업 복사본에 해제한다. 원본 압축·게임 EXE·선택 데이터의 SHA-256을 기록한다.
5. README·라이선스·화면 버전을 대조한다. installer/wrapper와 실제 게임 EXE를 구분한다.
6. `docs/reference/ASSET_REGISTER.md`에 파일별 출처·권리 근거·분석 전용/공개 후보/제외를 적는다.
7. 에뮬레이터에 해당 폴더만 마운트한다. 시작·이동·점프·종료를 확인하고 캡처한다.
8. 같은 시작 조건의 짧은 관찰을 3회 남긴다. 수동 키 입력은 결정적 replay 증거가 아니다.
9. `docs/evidence/G0_REPORT.md`에 명령·해시·캡처·확인/미확인·G1 첫 행동을 기록한다.

G0 완료는 역공학 성공이 아니다. 셰어웨어인지 불명확한 패키지는 공개 자산 채택을 보류한다.

## 8. G1 상세 순서와 중단 기준

1. 헤더·내부 모듈·압축·extender 여부를 확인한다. 파일 오프셋·분석 주소·실행 주소를 구분한다.
2. REA가 로드한 영역이 실제 게임 코드인지 확인한다. stub만 분석해 통과시키지 않는다.
3. 첫 질문: “이동 입력이 위치를 바꾸기 전에 어떤 충돌 검사를 거치는가?”
4. 함수·명령·참조를 조사하고 입력→이동→충돌 후보를 연결한다.
5. 벽 없음/있음, 키 누름/해제처럼 한 조건만 바꿔 원본을 관찰한다.
6. 후보와 실행 행동의 관계를 확인한다. 소스 대조는 별도 근거 열에 기록한다.
7. Lisp가 결정한 규칙은 `스크립트 규칙 + 바이너리 primitive`로 기록한다. 소스 열람을 디컴파일로 세지 않는다.
8. 입력 replay·상태 snapshot이 가능한지 검증한다. 화면 측정만 가능하면 오차와 비교 필드를 제한한다.
9. `docs/reconstruction/BEHAVIOR_MAP.md`, `docs/evidence/G1_REPORT.md`를 작성한다.

탐색 상한은 환경 정리 1시간+분석/실행 3시간이다. 자동 연장하지 않는다. 통과 기준은 실제 게임 코드 1경로+실행 연결+G2 측정 계약이다.

REA 불통과지만 같은 원본을 다른 도구로 분석할 수 있으면 도구 변경 근거를 남긴다. 분석 자체가 불가능하면 사용자에게 대상/범위 재결정 자료를 제시한다. Wumpus/Rogue 전환이나 소스 포팅으로 자동 대체하지 않는다.

## 9. G2–G3 구현 순서

| ID | 작업 | 수용 증거 |
|---|---|---|
| T01 | 입력·상태·시간·fixture schema | 누락/잘못된 기록을 거부 |
| T02 | 수평 이동·키 해제 | 원본 위치/정지 시점 비교 |

| T05 | 한 화면 Canvas·검사 명령 | 실제 조작과 `make check` |
| T06 | 조준·사격·피격 | 발사 간격/충돌/체력의 근거·범위 |
| T07 | 적 1종 | 복원 행동/독자 설계 행동 구분 |
| T08 | 맵·목표·결과·재시작 | 실제 시작→종료, 상태 초기화 |
| T09 | 조명 규칙 | 배터리 경계·일시정지·재시작, 물리 영향 없음 |

최소 복원 기준은 이동·충돌을 포함하는 핵심 동작 2개 이상이다. 다른 행동을 독자 설계했다면 그 범위를 명시한다. G2가 늦으면 신규 아트보다 비교를 먼저 해결한다.

## 10. 검사 명령 계약

다음은 G2에서 구현할 인터페이스다. 현재 존재하거나 통과했다고 가정하지 않는다.

| 명령 | 검사 |
|---|---|
| `npm run dev` | 로컬 앱 |
| `npm run typecheck` | 타입 |
| `npm run test:engine` | 규칙·경계 |
| `npm run reference:verify` | fixture 무결성·관찰 범위·실제 비교 |
| `npm run test:e2e` | 시작·플레이·종료·재시작 |
| `npm run build` | 정적 빌드 |
| `make check` | 타입+엔진+reference+build, 실패 전달 |
| `make smoke-local` | 브라우저 핵심 흐름 |

원본 캡처를 일반 gate에서 생성하지 않는다. fixture가 없으면 빈 집합 PASS 대신 NOT RUN으로 처리하고 필수 gate를 실패시킨다. 원본 EXE·private·미검토 자산이 공개 빌드에 섞이지 않게 한다. 정확한 판정은 [검증 계약](../reference/VERIFICATION_CONTRACT.md)을 따른다.

## 11. 플레이 검토와 시연

3명 관찰: 첫 조작까지 시간, 도움 없이 이해한 행동, 막힌 지점, 조명 비용 이해, 재도전 의향과 이유를 기록한다. 작은 표본으로 시장 수요를 입증하지 않는다.

영상 2분40초: 원본→새 게임 15초, 실제 플레이 40초, 주소→관찰→명세 30초, 비교/한계 25초, Kiro 실패 수정·hook 30초, 링크·마무리 20초. 원본 캡처와 실제 실행을 표시하고 고의 오류는 Demo mutation으로 명시한다.

완성도가 밀리면 추가 무기/적/맵, 복잡한 근거 UI, 장식 효과 순으로 줄인다. 실제 역공학 근거와 시작→종료 플레이를 삭제해 완료 처리하지 않는다.
