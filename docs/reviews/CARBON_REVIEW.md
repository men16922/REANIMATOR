# Gemini 4 Carbon 계획 리뷰

2026-11-14 · `gemini-4-carbon-high` · effort high · harness critic / plan mode

아래는 독립 리뷰 원문이다. 반영 결정은 별도 기록한다.

## 1) 판정

**조건부 진행 (핵심 규칙·검증 계약·일정 재배치 수정 후 P0 착수 권고)**

기존 대규모 Unity 프로젝트(`MYTHOS BLACKOUT`)의 직접 재출품을 피하고, 공개 고전(`Hunt the Wumpus`) 복원 위에 단일 변형 규칙(`Blackout`)을 얹어 신규성·시연 가능성·기존 설계 자산 공개(`docs/PREEXISTING_WORK.md`)를 모두 충족하려는 **방향성 자체는 Kiroween 규정과 잘 맞습니다.**

그러나 현재 초안은 ① **Blackout 조명 규칙이 원작 규칙과 충돌해 재미가 죽을 위험**, ② **조명 1회 사용 즉시 원본 기록 비교가 깨지는 변형 검증의 논리적 구멍**, ③ **공개 C 소스를 직접 컴파일해 다시 역공학하는 REA의 장식성**, ④ **B2C 플레이어 게임과 B2B 복원 도구 사이의 고객 혼선**, ⑤ **11/28 시험 전 ‘주 1시간’ 제약을 어기는 일정·범위 배치**가 해결되지 않았습니다. 아래 6개 항목을 먼저 고친 뒤 P0에 들어가야 시행착오를 막을 수 있습니다.

## 2) P0/P1 문제 (총 6개)

### [P0-1] 핵심 재미의 역설과 프로젝트 정체성을 무너뜨리는 자기모순 (재미 · 계획 모순)
- **게임성 결함:** 원본 *Hunt the Wumpus*는 이미 현재 방 진입 시 인접 3개 방의 위험 존재 여부(냄새·바람·박쥐)를 무료로 알려줍니다. 조명 규칙을 단순 *"인접 방 하나의 위험 유무 공개 + 괴물 반응 판정"*으로 두면, 위험 종류(구덩이 vs 움퍼스)를 특정하지 못할 경우 정보 이득이 없고, 반대로 괴물이 반응해 다른 방으로 이동해 버리면 **방금 조명으로 얻은 단서가 즉시 무효화되는 ‘죽은 선택지(Dead Mechanic)’**가 됩니다.
- **시간·공간 모순:** 3절 상단은 **90초 시연 안에 승패 확인(1판 40~60초)**을 전제하지만, 3절 하단은 한 원정을 **3–5분**으로 잡았습니다. 또한 원작의 핵심인 비유클리드 동굴 그래프(십이면체 20방, 방당 통로 3개)를 정의 없이 *"SVG/CSS 쿼터뷰"*로 그리면 화면상 인접해 보이는 방과 실제 통로 연결이 어긋나 첫 30초 플레이 직관성을 해칩니다.
- **축소 규칙 모순:** 2절에서는 *"Wumpus 포팅·검증만은 기술 데모에 머물고 나만의 게임 목표가 약하다"*며 기각해 놓고, 7절 축소 규칙 2번에서는 *"11/22 불안정 시 Blackout 변형을 보류하고 복원 경험 하나만 완성"*한다고 적어 **스스로 기각한 단순 포팅 데모로 회귀**합니다. 이 경우 첫 화면 주 버튼(`Play Blackout`), 사용자의 ‘나만의 버전 재제작’ 목표, 상품화 근거가 동시에 무너집니다.

### [P0-2] 조명 사용 순간 깨지는 변형 검증 계약의 허점 (변형 검증의 엄밀성)
- 계획은 *"원본과 같아야 하는 공통 행동만 비교하고 변경 규칙은 별도 수용 조건으로 판정"*한다고 선언만 했습니다.
- 그러나 C 원본은 단일 전역 난수(`rand()`) 스트림과 상태 위에서 돌아갑니다. Blackout 모드에서 플레이어가 **조명을 단 1번이라도 사용하는 순간**, 괴물 반응 판정으로 인해 **난수 오프셋과 괴물 위치가 원본 실행 기록(reference trace)에서 영구 분기(Diverge)**합니다.
- 분기 이후에는 플레이어가 일반 이동·사격을 해도 원본 세션 기록과 1:1 대조할 수 없으므로, **분기 뒤에 숨은 실제 이동·사격 구현 버그를 검증기가 잡지 못하거나 모든 턴이 diff로 덮이는 문제**가 발생합니다. ‘전체 세션 비교’와 ‘단일 턴(1-step) 오라클·불변조건 검증’을 분리하는 엄밀한 계약이 빠져 있습니다.

### [P0-3] 공개 C 소스를 직접 빌드해 역공학하는 REA의 장식성 및 `.kiro` 요건 누락 (REA 장식 여부 · 구현 근거)
- 5절 다이어그램은 **이미 보유한 공개 C 소스를 직접 컴파일한 뒤, 그 바이너리에 REA를 돌려 어떤 함수가 이동·사격을 처리하는지 찾겠다**고 설계되어 있습니다. *"소스를 감추는 연출을 하지 않는다"*고 밝혀도, 심사위원(Implementation·Innovation 각 20%) 눈에는 **옆에 있는 수백 줄짜리 C 소스를 두고 역어셈블러를 돌리는 장식적 파이프라인**으로 보입니다.
- REA가 장식이 아니려면 **소스 열람 전 바이너리만으로 명세 초안을 뽑고 원본 C 소스는 사후 채점지(Ground Truth)로만 대조하는 블라인드 검증 구조**여야 합니다.
- 동시에 해커톤 필수 제출 요건인 **공개 저장소 내 `.kiro` 디렉터리 포함 검증(특히 `.gitignore` 제외 방지)과 Kiro 산출물 구조**가 본문 규칙으로 박혀 있지 않습니다.

### [P1-1] ‘추리 게임 플레이어’와 ‘복원 개발자’ 사이의 대상고객 혼선 (대상고객 혼선)
- 첫 화면(`Play Blackout`)과 8절 1차 상품화는 **짧은 추리·위험 감수 게임을 찾는 PC 플레이어(B2C)**를 겨냥하지만, 프로젝트 제목(`REANIMATOR`), 1절 설명, 6절 Impact 증거(*"복원 개발자·보존 관심 사용자 3명 관찰"*)는 **개발자용 복원 검증 도구(B2B)**를 겨냥합니다.
- 일반 플레이어는 소스·기록 비교기를 열 이유가 없고, 복원 개발자는 Wumpus 한 작품만 고정된 웹 게임을 자기 업무 도구로 쓸 수 없습니다. Impact(20%)와 Design/상품화 서사가 서로 다른 고객을 향하고 있어 3분 미만 시연 영상의 메시지가 두 갈래로 쪼개집니다.

### [P1-2] ‘11/28 시험 전 주 1시간’ 제약을 초과하는 일정·범위 과부하 (일정 · 범위)
- **일정 충돌:** 오늘(11/14)부터 11/28 시험까지 사용자의 검토 시간은 **주 1시간(총 약 2시간)**뿐입니다. 그런데 P2(11/19–22) 통과 조건과 6절에 에이전트가 대신 수행할 수 없는 **외부 사용자 관찰(3명)**이 포함되어 있어 사용자 시간 제약을 즉시 초과합니다.
- **범위 과부하:** ① C 빌드·REA 분석, ② 2모드 쿼터뷰 게임(1440px·390px 모바일·키보드·사운드), ③ 브라우저 내장 인터랙티브 기록 비교기를 모두 만들려다 보니 시험 직후 4일(P4, 11/29–12/02)에 마감 작업이 과밀하게 몰려 있습니다.
- **제출 게이트 공백:** P5(12/03–04)에 사용자가 직접 권한으로 수행해야 할 **공개 OSS 저장소 전환·`.kiro` 노출 확인·3분 미만 시연 영상 녹화/업로드·Devpost 최종 제출**의 사용자 시간 예산이 분리되어 있지 않습니다.

### [P1-3] 미첨부 외부 문서 위임과 내부 메모 혼재로 인한 가독성 저하 (읽기 쉬움)
- 가장 핵심인 난수·검증 규칙과 Kiro 실행 기준을 본문에 확정하지 않고 상대 경로(`../reference/VERIFICATION_CONTRACT.md`, `../../REANIMATOR_KIRO_EXECUTION_SPEC.md`, `../STATUS.md`)로 넘겨, **이 계획서만으로는 규칙과 완료 기준을 판독할 수 없습니다.**
- `slice/power-grid`, `BLACKOUT dev-385`, `DEA 시험`, `untracked 두 경로` 같은 개인 로컬 상태 메모와 *"통과해야 확정"*, *"원본 조사 뒤 고정"* 같은 결정 유보 문구가 섞여 있어 실행 문서로서의 명확성이 떨어집니다.

## 3) 각 문제를 고칠 정확한 문구/규칙

아래 규칙과 교체 문구를 계획서의 해당 절에 직접 반영하십시오.

### [P0-1 수정] 3절 Blackout 규칙 확정 + 위상 시각화 고정 + 7절 축소 순서 역전
- **3절 ‘Blackout 모드의 최소 규칙안’ 교체 문구:**
  > - 한 원정의 목표 플레이 시간은 **60–90초(약 6–12턴)**로 설계하여 시연 흐름과 일치시킨다.
  > - 공간 표현은 **어둠 속 동굴 노드-통로 전술 뷰(SVG/CSS)**로 고정한다. 쿼터뷰 분위기 연출을 쓰더라도 현재 방과 연결된 **인접 3개 방의 통로 선은 항상 명확히 표시**하여 위상 혼선을 막는다.
  > - 플레이어는 한 원정에서 **조명(Flare)을 3회** 사용할 수 있다. 인접 방 하나(`X`)에 조명을 사용하면 `X`의 **정확한 상태(움퍼스·구덩이·박쥐·안전)를 영구 공개**한다(원본의 막연한 인접 경고를 확정 정보로 전환).
  > - **위험 대가:** 조명 사용 시 `X`에 **움퍼스가 있으면** 눈부심으로 그 턴에는 이동하지 않으나 경계 상태가 되어 다음 화살이 빗나가면 즉시 패배한다. 반대로 `X`에 **움퍼스가 없으면**(안전·구덩이·박쥐 확인 시) 빛과 소음에 반응해 동굴 어딘가의 움퍼스가 인접 방으로 1칸 이동 판정을 수행하며, 변경된 인접 냄새 신호를 즉시 갱신한다.
- **7절 ‘범위가 밀리면’ 2번 교체 규칙:**
  > 2. **축소 우선순위 고정:** 일정 지연 시 ① 브라우저 내장 인터랙티브 비교 UI를 ‘사전 생성된 검증 리포트 카드 3종’으로 단순화 → ② 사운드·배경 연출 축소 → ③ 390px 모바일 레이아웃을 플레이 화면만 지원(검증 상세 뷰는 데스크톱 전용) 순으로 줄인다. **프로젝트의 존재 이유인 `Classic 복원 + Blackout 조명 1규칙 + CLI 자동 검증 증거`는 어떤 경우에도 삭제하지 않는다.**

### [P0-2 수정] 3절 말미·5절 변형 검증 3단 계약 본문 명문화
- **5절에 추가할 ‘변형 검증 3단 계약’ 규칙:**
  > 1. **Zero-Light 동치 검증(전체 세션 비교):** Blackout 모드에서 조명을 0회 사용한 실행은 동일 초기 시드·동일 입력열에서 Classic 원본 실행 기록과 모든 턴의 방 이동·경고 출력·화살 판정·종료 사유가 100% 일치해야 한다.
  > 2. **PRNG 스트림 분리 계약:** 원본 행동 재현용 `classicRng`와 조명 반응 판정용 `blackoutRng`를 분리한다. 조명 미사용 구간에서는 `classicRng` 호출 횟수와 순서가 원본과 달라져서는 안 된다.
  > 3. **분기 후 1-스텝 오라클 및 불변조건(Frame Axiom) 검증:** 조명을 1회 이상 사용해 괴물 위치가 원본 기록과 분기된 뒤에는 전체 세션 재생 비교를 중단한다. 대신 ① 조명 실행 직후 **불변 상태(동굴 20방 연결 그래프, 구덩이·박쥐 위치, 남은 화살 수, 플레이어 현재 방)**가 변경되지 않았음을 스냅샷 diff로 검사하고, ② 분기 이후의 일반 이동·사격 각 턴은 **해당 턴 직전 상태를 Classic 규칙 엔진(1-스텝 오라클)에 넣은 결과**와 일치하는지로 구현 오류와 의도한 변형을 구별한다.

### [P0-3 수정] 5절 REA ‘블라인드 추출 → 소스 채점’ 격리 규칙 + `.kiro` 공개 게이트
- **5절 REA 조사 규칙 교체 문구:**
  > - **REA 블라인드 추출 프로토콜(장식 방지):** C 소스를 먼저 읽고 바이너리에 끼워 맞추지 않는다. P0에서 2 agent-hours 타임박스로 **컴파일된 바이너리만 REA에 입력**해 `이동·사격·종료 함수 후보와 rand() 소비 지점 가설`을 `.kiro` 조사 기록으로 먼저 커밋한다. 그 직후 원본 C 소스를 **사후 정답지(Answer Key)**로 삼아 REA 추출 적중 항목과 미탐지 경계 조건을 대조 표로 공개한다.
  > - **타임박스 탈출 규칙:** 2 agent-hours 내 REA 환경 연결이 실패하면 아키텍처 다이어그램·시연 영상·README 주 경로에서 REA를 즉시 제외하고 원본 소스+실행 계측만으로 진행한다.
- **9절 첫 작업 1번 보강 규칙 (`.kiro` 필수 요건):**
  > 1. 공개 저장소 루트의 `.gitignore`가 `.kiro/`를 무시하지 않음을 첫 커밋에서 검증한다. `.kiro/specs/classic-restoration/`과 `.kiro/specs/blackout-variant/`에 요구사항·설계·작업 목록을 작성하고, 실제 구현·실패 수정 시 Kiro를 통해 갱신된 이력을 커밋 단위로 남긴다.

### [P1-1 수정] 1절·6절 대상고객 및 Impact 서사 단일화
- **1절 정의 및 6절 Impact 교체 문구:**
